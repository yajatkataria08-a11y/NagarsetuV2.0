# Infrastructure Health — Evaluation

Status of every number and claim in the infrastructure-health feature, and what each one does and does not
establish. Written so that nothing here can be mistaken for a result on real bridges: **none of the learned
components has been evaluated on real structural data.**

## 1. Status at a glance

| Component | State | Evidence |

## 2. Datasets

**What is actually in the repository**

* `ai_engine/data/infra`, `ai_engine/data/crack_seg`: images generated by `ai_engine/infra/prepare_data.py`
  (`generate_synthetic_shm_sample`). They are synthetic. Earlier dataset YAML headers and the script docstring
  named CODEBRIM / SDNET2018 / Crack500; that was inaccurate and has been corrected.
* Vibration signals: simulated by `ai_engine/infra/vibration_data.py` — a noise-driven damped oscillator
  (f0 = 5 Hz, ζ = 0.02, fs = 128 Hz). Damage = stiffness loss (natural frequency × √(1−k), damping × (1+2k)).
  Healthy records vary f0 by ±2 % to stand in for temperature effects.

**Intended real sources (not downloaded or used)**

| Dataset | Use | Caveat |
|---|---|---|
| CODEBRIM | defect detection | format differs from a plain YOLO box set; a converter has not been written or tested |
| SDNET2018 | crack / no-crack | **classification only** (no boxes or masks) — cannot train a detector or segmenter by itself |
| Crack500 / CrackForest | crack segmentation | image+mask pairs; `ai_engine/infra/convert_masks.py` converts these to YOLO-seg with a leak-free split (tested on synthetic pairs only) |
| LANL 3-story frame, Z24 | vibration anomaly | `vibration_data.load_lanl` is an unimplemented stub |

Check each dataset's licence before redistributing images or trained weights.

## 3. Vibration anomaly detection (SIMULATED DATA)

Protocol: records split **by record** (1062 healthy train windows, 354 validation,
354 test; 1888 damaged test windows). Models see healthy data only. 2 s windows, features: RMS, kurtosis,
dominant frequency, spectral centroid, natural-frequency shift. Threshold = 99th percentile of the healthy
validation score. Generated by `python ai_engine/infra/train_anomaly.py` (seed 0).

Isolation Forest, all damage levels pooled: ROC-AUC **0.798**, F1 **0.384**, false-positive rate 0.008, recall 0.238.

| Damage level | ROC-AUC | Recall at threshold |
|---|---|---|
| 5 % stiffness loss | 0.546 | 0.011 |
| 10 % stiffness loss | 0.744 | 0.032 |
| 20 % stiffness loss | 0.916 | 0.189 |
| 30 % stiffness loss | 0.984 | 0.720 |

Reading this honestly: the model separates **severe** simulated damage well (AUC 0.98 at 30 %) but is near chance
at 5 %. The ±2 % healthy frequency drift is the same order as the shift a 5 % stiffness loss causes (≈2.5 %), so
small damage is not separable by design. Because the threshold is set for ≈1 % false positives, recall at the
operating point is low even where AUC is high (72 % at 30 % loss, 19 % at 20 %). The "healthy and damaged data separate
clearly" criterion is met only for the two largest damage levels. These numbers describe the simulator, not a structure.

A small interactive check (40 ten-second windows per condition, through the live service) saw healthy-window alarm rates between
3 % and 23 % depending on the generator; an alarm is evaluated as the maximum over the windows in a request, so
per-request false-alarm rate is higher than the per-window 1 % the threshold targets.

## 4. Crack measurement

Method: `skeletonize` → `distance_transform_edt` on the skeleton → width = 2d − 1 px (pixel-centre correction;
the plain 2×d rule reports a 1-px line as 2 px) → mm via `reference_mm / reference_px`.

Verified (synthetic masks): known widths 3, 7, 12, 20 px recovered within max(1 px, 10 %); a 1-px line reads 1 px;
diagonal length within 10 %; thin and wide synthetic cracks (3, 9, 20 px) are found by the classical mask.

Known biases and failure cases
* **Length reads short** by roughly one crack width (skeleton ends retract by ≈ w/2 each end).
* **Max width is a peak statistic.** In an end-to-end run a 9 px line measured 10.7 px (blur halo plus peak selection). Near a
  severity boundary (1.0 mm) that is enough to change the band.
* **Needs a reference scale.** Without it widths stay in pixels and no severity is assigned. The scale assumes the
  reference object lies in the crack's plane and the camera is square-on; perspective, lens distortion and surface curvature are not corrected.
* **Classical mask false positives:** shadows, joints, stains, rebar lines, and large dark regions can be marked as crack; low-contrast cracks are missed.
* **Severity bands (hairline < 0.3 mm, moderate 0.3–1.0 mm, severe > 1.0 mm) are not verified against IS 456:2000.**
  The permissible limit depends on exposure condition; confirm against your copy of the code before citing it.
  `measure.THRESHOLDS_VERIFIED` is `False` and every response says so.

## 5. Remaining useful life

Paris' law da/dN = C(Δσ·Y·√(πa))^m, integrated numerically on a log grid; Monte-Carlo 2 000 draws:
C lognormal (median 2e-12, σ_ln 0.5), m ~ N(3, 0.1), Δσ ±10 % uniform; returns P10/P50/P90 years.
Tested: numerical integral equals the closed form for m = 3 (rel. 1e-3); a hand-computed case
(a0 = 10 mm → ac = 40 mm, C = 1e-12, Δσ = 100 MPa, Y = 1) gives 1.79587e6 cycles; percentiles are ordered; longer cracks give shorter lives.

**Scope limit that matters:** Paris' law describes fatigue crack growth in *metal*. A crack measured on a photograph of
concrete is not such a crack, so feeding photo-measured length in as a0 illustrates the method and is not a prediction.
The UI and API say this. The material parameters are generic structural-steel values, not site-specific.

## 6. Health score and escalation

`score = 100 − (0.40·defect_risk + 0.35·anomaly_risk + 0.25·rul_risk)`; bands ≥ 70 good, 40–70 watch, < 40 critical.
Risk mappings are piecewise-linear judgement values (see `ai_engine/infra/health.py`). They have not been calibrated against
engineer condition ratings. If a component was never measured, the remaining weights are renormalised and the response lists
`components_used`; an unmeasured component is never scored as healthy. Components persist until replaced, so a stale
inspection can keep a score low after conditions change.

A score below 40 creates **one** hazard zone per structure (150 m, routing risk boost 2.0), marked `requires_verification`. Because inputs today
come from an untrained detector, a classical mask and a simulated-data anomaly model, an automatic zone can be a false alarm that changes citizen routing.
Review whether auto-escalation should be disabled until the models are trained on real data.

## 7. Reproduce

```bash
cd ai_engine
pip install -r requirements.txt          # pinned
python infra/train_anomaly.py            # regenerates metrics.json["anomaly"] + models/anomaly_*.joblib
pytest -q                                # AI tests
cd ../backend && npm ci && npm test      # needs AI_SERVICE_URL=http://127.0.0.1:8099 (stub started by the test)
```

To make the detection / segmentation numbers real (not done here): download a real dataset, convert it (`infra/convert_masks.py`),
train on a GPU (see `infra/NagarSetu_Infra_Training.ipynb` or `infra/train_local.py`), save weights **under a different hash than `best.pt`**, add the dataset
name and sha256 to `ai_engine/models/MANIFEST.json`, then run `infra/eval_detection.py --task detect|segment ... --dataset-label "<real dataset>"`.
It refuses weights identical to `best.pt`, evaluates the test split, and writes `metrics.json["detection"|"segmentation"]`.
